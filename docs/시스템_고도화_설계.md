# 멀티 타임프레임 트레이딩 AI 시스템 고도화 설계

## 1️⃣ 개선된 전체 시스템 아키텍처
설명

티커 변경 즉시 반영, 자산 자동 판별, TradingView 실제 차트, 예상 차트, 사용자 지정 시뮬레이션, 잔고 관리를 한 흐름으로 묶었습니다.

```text
[사용자 입력]
  ├─ 종목명 / 티커
  ├─ 시장 우선순위
  ├─ 분석 모드(실시간 / 과거분석 / 백테스트)
  ├─ 기준 프레임
  └─ 초기 잔고 / 통화
        ↓
[통합 Resolver]
  ├─ 코인 / 한국 주식 / 미국 주식 자동 판별
  ├─ 종목명 → 코드 변환
  └─ TradingView 심볼 변환
        ↓
[상태관리 계층]
  ├─ session_state 기본값 생성
  ├─ 선택 키(selection_key) 생성
  ├─ 종목 변경 시 symbol-scoped 상태 초기화
  └─ cache_data / cache_resource 키 분리
        ↓
[데이터 계층]
  ├─ MarketDataService.load_multi_timeframe_history
  ├─ yfinance / ccxt 실데이터 시도
  └─ 실패 시 deterministic demo OHLCV fallback
        ↓
[문맥 생성 계층]
  ├─ context_builder.build_context_from_histories
  ├─ Glenn Neely feature score
  ├─ 차설 target-zone / 공통구간 반영
  └─ strategy_state 생성
        ↓
[예측 계층]
  ├─ MTF 점수화
  ├─ 룰 엔진
  ├─ 리스크 매니저
  └─ XGB/LSTM/RF soft voting
        ↓
[표시 계층]
  ├─ TradingView 실제 차트
  ├─ Plotly 예상 차트
  ├─ 지지/저항/진입/익절/손절
  ├─ 사용자 지정 시뮬레이션 차트
  └─ 잔고 / 거래이력
        ↓
[포트폴리오 계층]
  ├─ BalanceManager
  ├─ 누적 손익 / 승률
  └─ 향후 멀티 포지션 확장
```

코드

```python
selection_key = build_selection_key(
    resolved,
    mode=분석모드_라벨[mode_label],
    analysis_timeframe=analysis_timeframe,
)
reset_symbol_scoped_state(st, selection_key)

histories = _load_histories_cached(
    resolved.as_dict(),
    분석모드_라벨[mode_label],
    required_timeframes,
    lookback_bars,
)
context = build_context_from_histories(
    resolved,
    histories,
    mode=분석모드_라벨[mode_label],
    account_equity=snapshot.total_equity,
)
prediction = run_pipeline(context)
```

## 3️⃣ 대시보드 상태관리 설계
설명

핵심은 종목마다 `selection_key`를 다르게 만들고, 종목 스코프 상태만 지워서 이전 종목 데이터가 남지 않게 하는 것입니다.

코드

```python
def ensure_session_defaults(st) -> None:
    if "active_selection_key" not in st.session_state:
        st.session_state.active_selection_key = ""
    if "portfolio_state" not in st.session_state:
        st.session_state.portfolio_state = None
    if "trade_results" not in st.session_state:
        st.session_state.trade_results = []


def reset_symbol_scoped_state(st, selection_key: str):
    changed = st.session_state.get("active_selection_key") != selection_key
    if changed:
        for key in _SYMBOL_SCOPED_KEYS:
            st.session_state.pop(key, None)
        st.session_state.active_selection_key = selection_key
```

## 1️⃣1️⃣ 업로드 파일 5개의 반영 위치 및 방법 정리
설명

문서별 반영 위치는 아래와 같습니다.

- `차설 지표`
  - `build_context_from_histories`에서 `common_zone_hit_flag`, `entry_signal_on_3m`, `entry_signal_on_5m`, `entry_signal_on_15m`, `lower_tf_exit_priority`, `nearest_target_distance` 생성
  - `build_exit_plan`에서 하위 TF 우선 청산 반영
- `spd 매매원칙`
  - `rule_registry.py`에서 `stop_clear`, `no_chasing`, `pattern_confirmed`, `one_candle_one_trade`, `reward_risk_floor`
  - `risk_manager.py`에서 손절 명확성 / FOMO / 이벤트 리스크 반영
- `spd 매매타점`
  - `context_builder.py`에서 `bullish_divergence_flag`, `bearish_divergence_flag`, `flag_pattern_confirmed`, `retest_success_flag`
- `요약 / 엘리어트 / 피보나치`
  - `context_builder.py`에서 `fib_retracement_zone_class`, `fib_extension_zone_class`, `estimated_wave_stage`, `abc_completion_flag`
- `글렌닐리 PDF`
  - 자동 파동 카운팅 대신 `wave_two_retracement_ratio`, `wave_three_extension_ratio`, `wave_four_overlap_risk`, `wave_five_extension_ratio`, `triangle_e_undershoot_flag`, `diagonal_candidate_flag`를 feature / validation score로 반영

코드

